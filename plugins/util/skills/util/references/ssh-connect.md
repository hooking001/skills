# SSH 서버 등록·연결

로컬 에이전트에서 실행한다. Python 3와 OpenSSH가 필요하다. 아래 `HELPER`는 `util/SKILL.md` 옆 `scripts/ssh_connect.py`의 **실제 절대 경로**로 치환한다. 플러그인 캐시 경로를 하드코딩하지 않는다.

서버 목록과 연결 소켓은 `~/.ssh/ssh-connect/`에 저장한다. 플러그인 업데이트와 프로젝트 변경 후에도 서버를 이름으로 찾을 수 있다. 비밀번호·OTP·키 내용은 묻거나 저장하지 않는다. 기존 `~/.ssh/config`는 수정하지 않으며 SSH 별칭, 키, ProxyJump 설정은 OpenSSH가 읽는다.

## 서버 등록

1. `python3 "HELPER" list`로 이미 등록된 서버를 찾는다.
2. 대화에서 이름, 호스트, 사용자, 선택 항목인 포트·점프 호스트·작업 경로를 추출한다. 빠진 필수 정보만 한 번에 묻는다. 기존 SSH 별칭이면 사용자·포트는 생략해 기존 설정을 따른다. 예: "개발 서버로 id@a.b.c.d 등록해줘".
3. 등록 명령을 실행한다. 이름은 한글도 가능하다.

   ```bash
   python3 "HELPER" register '개발 서버' --host a.b.c.d --user id --workdir /home/id/project
   # 기존 ~/.ssh/config의 별칭 활용
   python3 "HELPER" register '연구 서버' --host research
   ```

   `--port 2222`, `--jump id@bastion`도 지원한다. 다른 내용으로 등록된 이름은 자동 덮어쓰지 않는다. 사용자 요청이 기존 등록 변경을 명시할 때만 `--replace`를 쓴다.
4. 등록 위치와 이름을 짧게 알린다. 등록만 요청했다면 연결하지 않는다. 등록 후 접속도 요청했다면 바로 아래 연결 절차를 따른다.

## 이름으로 연결

1. 항상 `list`로 로컬 등록을 조회한다. 정확한 이름이 없으면 명백한 단일 후보를 선택하고 알린다. 후보가 여러 개이면 선택을 묻는다. 미등록 서버이면 등록에 필요한 정보만 묻는다.
2. `python3 "HELPER" connect '개발 서버'`를 실행한다.
   - `connected`: 기존 연결을 재사용한다. 로그인 창을 추가로 열지 않는다.
   - `login_required`: 로그인용 터미널을 열었다. **"열린 터미널에서 비밀번호·OTP로 로그인해 주세요. 로그인 후 알려주시면 이어서 진행하겠습니다."**라고 안내한다. 터미널을 열었다는 이유로 연결 성공을 보고하지 않는다.
   - `manual_login_required`: GUI 터미널을 열 수 없는 환경이다. 출력된 `login_command`를 사용자에게 주고 별도 일반 터미널에서 직접 실행하도록 안내한다. 원격 서버에 Claude를 설치하라고 바꾸지 않는다.
3. 사용자가 로그인했다고 하면 `python3 "HELPER" status '개발 서버'`로 확인한다. 가능하면 사용자 응답을 기다리는 동안 짧은 상태 확인으로 인증 완료를 알아볼 수 있지만, 장기 폴링하거나 창을 반복해서 열지 않는다. 상태 확인 실패만으로 연결을 종료하지 않는다. 인증 실패라면 열린 터미널의 오류를 사용자가 확인하도록 한다.
4. `connected` 확인 후 `run '개발 서버' -- 'hostname; pwd'`로 실제 명령 실행을 검증한다. 요청한 작업이 있으면 이어서 수행한다. 로그인용 터미널을 열어둬야 연결이 유지되고, 그 터미널의 `exit` 또는 `disconnect`로 종료할 수 있다고 알린다.

macOS는 기본 Terminal.app, Linux는 설치된 gnome-terminal·konsole·xterm 중 하나를 연다. 사용자가 직접 로그인할 터미널은 에이전트의 출력 수집 도구를 통하지 않는다. 창 열기가 거부되면 이유를 알리고 수동 로그인 명령을 제공한다. 에이전트 샌드박스 때문에 소켓·GUI 접근이 차단되면 해당 명령에 필요한 접근만 사용자 설정에 맞게 허용받는다. 전역 권한이나 샌드박스를 임의로 끄지 않는다.

## 원격 명령과 파일 전송

이 헬퍼는 연결 소켓을 확인하고 기존 연결만 사용한다. 연결이 없으면 새 인증 대신 실패한다. 이 경우 연결 절차로 돌아가 사용자가 직접 로그인하게 한다.

```bash
# 명령 문자열은 로컬 셸에서 한 인자로 전달한다. 원격에는 bash -lc로 전달된다.
python3 "HELPER" run '개발 서버' -- 'git status --short'

# 등록한 작업 경로 대신 이번 명령에만 다른 경로 사용
python3 "HELPER" run '개발 서버' --cwd /tmp -- 'ls -la'

# 업로드: 로컬 경로 → 원격 절대 경로
python3 "HELPER" upload '개발 서버' ./input.txt /tmp/input.txt

# 다운로드: 원격 절대 경로 → 로컬 경로
python3 "HELPER" download '개발 서버' /tmp/result.txt ./result.txt

# 디렉터리는 --recursive 추가
python3 "HELPER" upload '개발 서버' ./data /tmp/data --recursive

python3 "HELPER" disconnect '개발 서버'
```

등록된 작업 경로는 `run`에만 적용한다. 전송의 원격 경로는 절대 경로로 지정한다. 매 `run`은 별도 셸이므로 이전 `cd`, 변수, 대화형 프로그램의 상태를 이어받지 않는다. 상태가 필요한 작업은 하나의 명령으로 묶거나 원격 tmux를 별도로 사용한다. 원격 파일은 로컬 Read/Edit 도구로 바로 열리지 않는다. SSH로 읽거나 내려받아 수정한 뒤 업로드한다. 원격 작업 범위는 현재 사용자 요청을 따른다.

등록은 `list`, `register --replace`, `remove`로 관리한다. 연결 중인 서버의 변경·삭제는 먼저 연결 종료가 필요하다. 삭제는 로컬 등록만 제거하며 원격 파일은 건드리지 않는다.
